# VoiceDiet Orb — 3D-реконструкция сферы ассистента

Источник: `VoiceDiet 3_0.pdf`, слайд 1. Сфера в PDF состоит из двух картинок:
- **оболочка**: белые точки, вся форма задана альфа-маской 1971×1987;
- **ядро**: картинка-пузырь 280×280, повёрнута на ~208° и обрезана кругом.

Обе картинки извлечены из PDF без пересжатия (`scripts/extract_reference.py`).

## Что лежит в папке

| Файл | Назначение |
|---|---|
| `blender/voicediet_orb.blend` | Редактируемый исходник: ядро с шейдером на нодах, оболочка (меш икосферы, точки через Geometry Nodes `VD_ShellDots`), камера референса |
| `export/voicediet_orb.glb` | GLB: `VD_Orb` → `VD_Core` (сфера + PBR), `VD_Shell` (10 242 точки, POINTS, атрибут `_REST_DIR`), `VD_Camera` |
| `viewer/` | Интерактивный просмотр на Three.js: вращение, ракурс референса, слои, наложение оригинала |
| `renders/threejs_ref_view.png` | Рендер с ракурса референса (Three.js, 1024², на фоне слайда) |
| `renders/blender_ref_view.png` | Тот же ракурс в Blender Cycles (прозрачный фон) |
| `renders/voicediet_orb_turntable.mp4` | Облёт 360°, 96 кадров, 1024², H.264 |
| `renders/turntable/view_*.png` | Виды спереди, сбоку, сзади, сверху и снизу |
| `qa/comparison_board.png` | Сравнение: рядом, 50/50, разница, точки, силуэты, метрики |
| `qa/threejs_metrics.json`, `qa/glb_verify.json` | Числовые проверки |

## Устройство модели

- **Ядро `VD_Core`.** Сфера R = 1. Цвет считается от нормали в пространстве камеры: розовая база, маджента/фиолет справа снизу, белое пятно с ореолом, эллиптический нижний блик и голубой френелевский край. Параметры подобраны по пикселям ядра из PDF (`build/core_fit.json`). Одни и те же параметры используют ноды Blender и GLSL просмотрщика.
- **Оболочка `VD_Shell`.** Икосфера с 5 уровнями деления (10 242 вершины). Тип сетки определён по референсу: в центре гексагональная решётка с тремя одинаковыми периодами под 60°, видны пятиугольные «сходящиеся» узлы, плотность в центре ≈154 px² на точку. UV-сфера проверялась и не подошла. Деформация состоит из двух частей: гладкого векторного поля (гармоники, касательный сдвиг только на низких частотах) и повершинного смещения вдоль нормали со сглаживанием. Всё подобрано дифференцируемым рендером точек по альфе PDF (`scripts/fit_shell.py`).
- **Точки.** Профиль измерен по маске: гауссиана σ ≈ 1.9 px кадра 1024, пик ≈ 1. Задние точки перекрываются ядром — в референсе внутри диска ядра видна только передняя решётка.
- **Камера.** Перспектива, FOV 30°, дистанция 5.372. Радиус ядра на кадре — 362 px из 1024.

Ядро и оболочка — отдельные объекты со своими материалами, общий родитель `VD_Orb`. У оболочки сохранён атрибут `rest_dir`/`_REST_DIR` (направление недеформированной сферы) для будущей анимации.

## Что переносится в GLB, а что нет

- Геометрия, иерархия, камера и атрибут точек переносятся без потерь. Проверено повторным импортом в Blender: максимальная ошибка координат 2.4·10⁻⁷.
- Шейдер ядра (функция нормали в пространстве камеры) в glTF **не описывается**. В GLB ядро получает упрощённый PBR `VD_Core_GLTF`: розовая база, маджента-эмиссия, coat. Точный вид восстанавливает `viewer/orb.js` по `viewer/core_params.json`.
- Мягкие гауссовы точки в glTF не задаются: POINTS рисуются квадратами 1 px. Мягкие точки реализует шейдер просмотрщика. В Blender точки рендерятся твёрдыми дисками r = 2.2 px (уровень 0.5 гауссианы).

## Запуск

```bash
py -m http.server 8765 --bind 127.0.0.1 --directory voicediet-orb
```
Откройте http://127.0.0.1:8765/viewer/. Ползунок «Оригинал» накладывает кадр из PDF в ракурсе референса.

Полная пересборка (из папки `voicediet-orb`):
```bash
py scripts/extract_reference.py
py scripts/fit_core.py
py scripts/fit_shell.py --trials 3000 --top 4 --iters 1500 --h_iters 3000 --h_smooth 12
py scripts/fit_shell.py --init build/shell_fit_v1.json --h_iters 1500 --h_smooth 12 --sil_w 0.25
../tools/blender-4.5.14-windows-x64/blender.exe -b --factory-startup --python scripts/blender_build.py -- --samples 128
node scripts/capture.mjs && py scripts/compare.py threejs && py scripts/compare.py blender
```
После `fit_core.py` скопируйте `build/core_fit.json` в `viewer/core_params.json`.

Зависимости (бесплатные): портативный Blender 4.5.14 LTS в `../tools/`; Python-пакеты `pymupdf`, `pillow`, `numpy`, `torch` (CPU), `scipy`; three 0.186.1 (скопирован в `viewer/vendor`); Chrome Headless Shell из Remotion; FFmpeg.

## Сравнение с референсом (ракурс референса, Three.js)

- IoU силуэта оболочки: **0.978**
- Корреляция плотности точек при размытии 2 / 4 / 8 px: **0.82 / 0.97 / 0.99**
- Средняя альфа точек: 0.128 (в референсе 0.126)
- RMSE кадра после размытия 3 px: 3.6 / 255; в зоне ядра — 4.5 / 255
- Blender Cycles: RMSE после размытия 3.8 / 255, в зоне ядра 4.5 / 255

## Оставшиеся расхождения

1. **Отдельные точки не совпадают.** Складки, полосы и силуэт совпадают, но фаза решётки (где именно стоит каждая точка) по одному кадру не восстанавливается. Видно при увеличении и на карте разницы.
2. **Край оболочки.** Мелкие «иглы» справа (горизонтальные ряды точек) и часть рваного верхнего гребня переданы мягче. Самые резкие складки сглажены регуляризацией.
3. **Ядро.** Горячее пятно в оригинале компактнее и белее, у модели шире. Нижний блик и голубизна края справа снизу немного слабее. Зернистые полосы JPEG-текстуры исходной картинки 280 px не воспроизводились намеренно.
4. **Центр.** Центр ядра в PDF смещён на ~3 px вверх относительно центра оболочки; модель концентрична.
5. **Освещение ядра привязано к камере** (как matcap). При вращении ядро выглядит одинаково, вращается только оболочка. Так вид совпадает с макетом с любого ракурса; сменить на мировое освещение можно в шейдере.

## Что восстановлено предположительно (не видно на референсе)

- **Задняя половина оболочки.** Её закрывает ядро, а по краю видна только кромка. Форма сзади — продолжение того же гладкого поля без подгонки, поэтому сзади складок меньше, чем спереди (см. `renders/turntable/view_az180_el0.png`).
- **Глубина складок вдоль луча зрения.** Один кадр её не фиксирует. Ограничена радиусом 1.03–1.42 и гладкостью.
- **Ориентация икосаэдра.** Выставлена по двум видимым пятиугольным узлам — оценка, а не измерение.
- **Тип сетки и число точек.** Выведены из измерений, исходного файла 3D-сцены нет.

Для точного совпадения нужен исходник (C4D/Blender/AE) или 2–3 дополнительных ракурса той же сферы.
